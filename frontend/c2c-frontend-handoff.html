Start with the docs

The backend exposes a live, interactive API reference (Swagger UI). Every endpoint is there — its method, the request body shape, the response shape, which fields are required, and whether it needs login. You can even fire test requests straight from the page.

Swagger UI — live API reference https://<the-deployed-url>/api/docs ↗
Note

Akash will share the deployed base URL once it's live. Until then, you can run the whole backend locally with one command (docker compose up) and hit http://localhost:5000/api/docs. Ask him for the .env values you'll need.

Treat Swagger as the source of truth. If the docs and any older message disagree, the docs win — they're generated from the actual route code.

02

How to read an endpoint

In Swagger, each endpoint expands to show everything you need. A quick orientation:

  • Tags group endpoints by feature — Sessions, Contests, Hackathons, Forum, Leaderboard, and so on. Browse by the thing you're building.
  • A lock icon means the endpoint needs the user to be logged in. No lock means it's public.
  • Required fields in a request body are marked with a red asterisk. Everything else is optional.
  • The responses section shows the success shape and the error codes you should handle (e.g. 400 validation, 403 not allowed, 404 not found, 429 rate limited).

Every successful response follows the same envelope, so you can write one helper to unwrap it:

// success
{ "success": true, "data": { /* ... */ } }

// failure
{ "success": false, "message": "Human-readable reason" }
03

Auth: the one thing to get right

This is the most important integration detail, so read it twice. Auth uses an HttpOnly cookie, not a token you store yourself.

What that means for you

  • You cannot read the auth token from JavaScript — that's intentional (it's safer against XSS). So there's no localStorage.setItem('token', ...) here.
  • The browser stores and sends the cookie automatically. You just have to tell it to include credentials on every request.
  • Login happens through Google. You send the user to the backend's Google login route; after they authorize, the backend sets the cookie and redirects back to the frontend.

The non-negotiable setting

Every request to the API must include credentials, or the cookie won't be sent and the user will look logged out:

// fetch
fetch(`${API}/api/users/me`, { credentials: "include" })

// axios — set once, globally
axios.defaults.withCredentials = true
CORS

The backend only accepts requests from one frontend origin (set via FRONTEND_URL). Give Akash the exact URL your app runs on — http://localhost:3000 in dev, and your real domain later — or the browser will block your calls.

The login flow, end to end

// 1. send user to Google login (full redirect, not fetch)
window.location.href = `${API}/api/auth/google`

// 2. backend handles Google, sets the cookie, redirects back to your app

// 3. on app load, ask "who am I?" — cookie rides along automatically
const me = await fetch(`${API}/api/auth/me`, { credentials: "include" })
// 401 → not logged in. 200 → you get the user object.
04

Two flows worth knowing early

Profile completion gate

A brand-new user has isProfileComplete: false. Right after first login, check this on the user object and route them to a "complete your profile" screen (phone + HackerRank username) before letting them into the app. Submit it to the profile endpoint, which flips the flag to true. The year is derived automatically from their college email — never ask for it.

Image uploads (forum & avatars)

The backend never receives the image file. Instead it's a signed direct upload:

  • Ask the backend for an upload signature (tell it the folder: forum or avatars).
  • Upload the file straight to Cloudinary with that signature — you get back a URL.
  • Send only the URL to the backend (in the forum post body, or the avatar endpoint).
05

Picking your stack

Your call entirely — here's an honest read for an intermediate dev building a cookie-auth, REST-backed app like this one.

Solid default

Next.js (App Router) + TypeScript

Routing, structure, and great DX out of the box. Works cleanly with cookie auth (just send credentials: "include" from the client). TypeScript pairs naturally with the typed API. The safest "it'll scale and look professional" choice.

Lighter

React + Vite + TypeScript

If you don't need SSR or server components, this is faster to spin up and simpler to reason about. A pure SPA talking to the REST API is perfectly fine for this project. Add React Router for navigation.

Regardless of framework, these earn their keep

  • TypeScript — the API shapes are well-defined; typing your responses catches bugs before runtime.
  • TanStack Query (React Query) — handles fetching, caching, loading and error states. It'll save you from re-inventing data-fetching by hand for every screen.
  • A small API wrapper — one file that sets the base URL and credentials: "include" once, unwraps the { success, data } envelope, and throws on success: false. Import it everywhere.
  • Tailwind or a component library (shadcn/ui, Mantine) — for speed and consistency. Pick one and commit.
06

Gotchas that'll save you time

  • Forgot credentials: "include"? Every authed call returns 401 even though login "worked." This is the #1 thing to check first.
  • CORS error in console? Your frontend origin isn't on the backend's allowlist. Send Akash your exact dev URL.
  • Leaderboard needs a year. /api/leaderboard requires ?year=1|2|3|4 — there's no "all years" view by design. Calendar's year filter is optional.
  • Hackathon detail changes by role. The same endpoint returns different fields for a guest, a member, and an admin. Build the UI to handle fields being present or absent, not assume.
  • Contest links can be locked. A gated contest hides its link (isLocked: true, URL is null) until the user submits the access code — or until the contest ends, after which it opens automatically.
  • Rate limits exist. Hitting an endpoint too fast returns 429. Don't fire requests in tight loops; debounce things like search or upvote toggles.
07

Before you start — quick checklist

  • Get the deployed base URL (or run the backend locally via Docker)
  • Send Akash your frontend's exact origin for the CORS allowlist
  • Open /api/docs and skim the tags to see the whole surface area
  • Set up your API wrapper with credentials: "include" first, before anything else
  • Build the login → /auth/me → profile-completion flow before feature screens
  • Pick your stack and component library, and commit to it

Questions about a specific endpoint? Check Swagger first — then ping Akash.
